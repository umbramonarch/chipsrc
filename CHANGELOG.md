## [Unreleased]

### Performance

- **Packed Cache Shards for Large Repositories & Restored Incremental Emit Budgets (`model.rs`, `scanner.rs`, `emitter.rs`, `lib.rs`)**:
  - Repositories with more than 500 source files now store their per-file AST cache as deterministic 64-unit packs (`cache/pack-<16hex>.json`, name = BLAKE3 over the chunk's rel_path-sorted `(rel_path, blake3_hash)` pairs) instead of one tiny file per source file. A fresh STM32CubeF4 conversion creates **195 packs instead of 12,471 files** (`cache/` = 197 JSON files total), which removes the ~17 s of small-file creation that previously dominated the cold emit tail. `cache/manifest.json` keeps `CACHE_SCHEMA_VERSION` `2.1.0`; each member's `shard` points at its pack. Repositories with `<= 500` files keep the existing one-shard-per-file layout byte-for-byte.
  - `scanner::load_cache_shard_units` / `load_cache_shard_unit` / `load_cache_units` recognize both layouts, read each pack exactly once per pass, look the unit up by `scanned.rel_path`, and re-attach per-file fields. `load_cache_file` groups manifest entries by shard so a packed cache loads each pack once; the clean/dirty split is layout-independent (content hash), and the digest-noop and coordinate-shift tiers rewrite only the affected pack (`rewrite_cache_shards_for_dirty_units`, `emit_cache_manifest`).
  - `CacheShardWriter` now decides shard reuse from the previous manifest **before** any JSON serialization or structural-digest hashing (`prev.blake3_hash == hash && prev.shard == expected_shard && digest present && file exists`), so a 1-file edit over 123 files serializes one unit instead of 123.
  - `write_streamed_file` renders every existing table `<= 8 MB` in memory and hands it to `write_bytes_atomic` (read + compare, skip write/rename when identical); larger tables (`xref.tsv` at 12k-file scale) keep the streaming `.tmp` path. On incremental syncs (all six index tables present and `<= 8 MB`) the tables, `INDEX.md`/`sections/*.md`, and `cache/graph_state.json` are rebuilt concurrently with parallel per-table row formatting (`build_table_bytes`), keeping pure-CPU formatting off the critical path.
  - Measured on this machine (rotational D: volume): `smart_locker` 1-file structural edit — median `emit 27 ms` / `total 85 ms` over three `[1/122 reparsed/reused]` rounds (was `emit 54 ms` / `total 123 ms`; budgets `< 50 ms` / `< 100 ms`), and `index/` + `sections/` + `INDEX.md` are byte-identical to `convert --force` (33 artifacts, 0 differing SHA-256). STM32CubeF4 fresh `--force --vendor-mode all` — median `link 3,149 ms` (budget 14,350), `emit 8,118 ms` (budget 16,450), `total 24,346 ms` (budget 40,000), peak working set `1.4652 GiB` (budget 1.5 GiB); two independent cold bundles are byte-identical across `index/`, `sections/`, `INDEX.md`, and `cache/` (1,705 files, 0 diffs). ETL cold `link 556 ms` (budget 17,500).
  - Restored the dogfood `external_or_macro` guard to `< 15%` (measured `14.35%`): the new `#[cfg(test)]` helpers use free functions instead of closure-local calls, dogfood queries pass bundle slices directly instead of `std::slice::from_ref`, and the internal pack-rewrite helper is `pub(crate)`.
  - Tests: packed shard determinism/round-trip/reuse, single-pack rewrite with sibling preservation, digest-noop pack and per-file rewrites, guarded parallel table bytes, packed cache loader round-trip, and `invariants.rs` end-to-end coverage for a 505-file packed repository (cold → digest-noop → coordinate-shift → structural, byte-identical to `--force` and reproducible across independent builds).

- **Fast `macro`/`reg` Queries, Serial Section Writes, Single Cache-Dir Scan & Lower Cold-Path Working Set (`query.rs`, `emitter.rs`, `lib.rs`, `resolver.rs`)**:
  - `index/macros.tsv` queries now walk the table as raw bytes with `memchr` line offsets and a sound prefilter on the raw row (trimmed query, peripheral stem, or trailing register segment on the name column; contiguous hex digits ignoring `_` for address queries) before any column splitting. Hex normalization only runs for hex queries, `ascii_contains_ignore_case` finds candidate starts with `memchr2`, and `bundle_name_from_dir` reads `metadata.repo_name` from a 64 KiB prefix instead of materializing every `file_stamp`. On STM32CubeF4 (492,434 macros, 101 MB) `reg GPIO_MODER --json --limit 10` went from `1,020 ms` to `139 ms` with `--no-sync` and from `1,158 ms` to `362 ms` median with auto-sync (budget 500 ms), returning byte-identical JSON.
  - `sections/*.md` shards are written by one ordered stream instead of two `rayon` streams (measured `8.6 s → 4.2 s` for 1,501 fresh shards on the rotational test disk), a bundle without a `sections/` directory skips the shard-directory listing/prune and creates shards directly, streamed tables skip BLAKE3 hashing when there is no previous file to compare, and `CacheShardWriter` hands its `cache/` listing and parsed `manifest.json` to the manifest emitter instead of paying for a second directory scan and JSON parse.
  - `convert_repo` joins the cache-shard worker before emitting and then drops the parsed units and scanned-file list, so the 12k-file cold path writes tables/sections without ~400 MB of parsed AST alive (`emit_bundle` takes a `CacheShardSource`: prewritten shard identities or units). Peak working set on STM32CubeF4: `1.475 GiB → 1.455–1.464 GiB`.
  - `resolver::collect_symbol_tables` pre-sizes the symbol/type/macro tables and deep-clones rows in 500-unit parallel batches (deterministic order preserved) before the existing sort/dedup/header-prototype merge.
  - Byte-identical output: two independent cold STM32CubeF4 bundles and the pre-change reference bundle all compare `0` differing SHA-256 across `index/`, `sections/`, and `INDEX.md` (1,508 artifacts each).

- **Parallel Stat-Only Warm Path & Single-Parse Bundle Gates (`scanner.rs`, `lib.rs`, `query.rs`)**:
  - `scanner::stamp_check` now walks with `ignore::WalkParallel` (one worker per core) and classifies entries on the walker threads through a per-thread accumulator merged after traversal; unchanged files are still verified by `(size_bytes, mtime_secs, mtime_nanos)` alone and never opened. `.gitignore`/`.ignore`/`.claudeignore` rules keep being parsed once per directory by the ignore crate's per-directory matcher stack, and `FxHashMap<rel_path, stamp_index>` replaces the previous per-file reference map.
  - Added `scanner::BundleArtifactSources`, `scanner::first_missing_bundle_artifact_with`, and `scanner::bundle_artifacts_complete_with`, so `convert_repo`, `auto_refresh_bundles`, and `workspace_status` reuse one parsed `meta.json` (~4 MB on STM32CubeF4) and `auto_refresh_bundles` parses `cache/manifest.json` exactly once per bundle instead of once per gate.
  - STM32CubeF4 (12,471 files, 4.57M lines) warm `ensure --timings`: `scan`/`total` `2,238 ms → 204–243 ms` (median `204 ms` of 3 `CACHE HIT` runs with unchanged `index/*` hashes); `type GPIO_TypeDef --json` with auto-sync `1,960 ms → 263 ms` median versus `44 ms` with `--no-sync` and byte-identical rows. `smart_locker` warm cache hit `31 ms → 11 ms`; its 1-file structural sync stays at `91–95 ms`.
  - Tests: `stamp_check_never_reads_unchanged_file_content` (rewrites the body to a different same-size program and restores the exact mtime — the check must still report unchanged), `stamp_check_parallel_walk_covers_nested_files_adds_and_deletes`, `stamp_check_parallel_walk_honors_gitignore_and_claudeignore`, and `bundle_artifacts_complete_with_reuses_parsed_metadata`.

- **Coordinate-Shift Incremental Tier (Tier 3) & Persisted Linked-Graph State (`model.rs`, `lib.rs`, `emitter.rs`, `resolver.rs`, `sharder.rs`)**:
  - Added `cache/graph_state.json` (schema `2.1.0`, written atomically next to `cache/manifest.json` and excluded from shard pruning) storing the linked-graph results that cannot be re-derived from the AST: per-symbol PageRank/HITS/degree/SCC annotations plus god nodes, entrypoints, layer edges, cycles, and the active vendor surface. It is refreshed on every full conversion and on every Tier 3 sync, so it always describes the on-disk bundle.
  - `convert_repo` now detects coordinate-only dirty batches (every dirty file keeps its `structural_digest`, scope, and architecture layer while line coordinates or docstrings moved, no files added/deleted, no file reaches the `1,400`-line single-file threshold, and no module group exceeds `3,000` lines / `8` files). For those it rebuilds the symbol/type/macro tables with the shared `resolver::collect_symbol_tables`, re-attaches the persisted graph metrics 1:1, re-coordinates `index/calls.tsv`/`index/xref.tsv` from zipped old/new AST lists, and re-runs `build_section_shards` + `emit_bundle` **without** executing `resolve_and_link` or `analyze_graph` (`link=0ms graph=0ms` in `--timings`).
  - Any reconstruction failure (missing/truncated/schema-mismatched `graph_state.json`, unparsable or incomplete index tables, conflicting line translations, shard-shape drift) falls back to the full structural path, which now deletes `graph_state.json` before relinking so a failed emit can never leave stale annotations next to fresh tables. Tier 3 output (`index/*`, `sections/*`, `INDEX.md`) is byte-identical to `convert --force`. C/C++ dirty files fall back because header-prototype doc transfer can rewrite another file's docstring.
  - Added `RepoMetadata.incremental_tier` (`cache_hit`, `digest_noop`, `coordinate_shift`, `structural`) for observability, plus `resolver::collect_symbol_tables`, `sharder::shard_group_key`, `sharder::coordinate_shift_grouping_stable`, and a shared `synchronize_indexed_sections` helper used by the structural and coordinate-shift paths.
  - Raised the `INDEX.md` **Core Domain Types & Data Structures** table cap from 12 to 15 rows so the core pipeline types (`ConvertConfig`, `ChipsrcError`, `ConversionBundle`, `ParsedFileUnit`, `ExtractedSymbol`, …) stay listed as the codebase grows.
  - Added tier-selection/line-map unit tests and `invariants.rs` end-to-end coverage for the coordinate shift (`link_ms == 0`, `graph_ms == 0`, shifted `start_line`/`end_line`, `sections/*.md` coordinates, byte-identical to `--force`), docstring-only shifts, the 1,398 → 1,498-line threshold fallback, truncated `graph_state.json`/`meta.json` self-healing, and invalid-UTF-8/Unicode sources with repeated Unicode concept searches.

- **Zero-Alloc `sanitize_tsv`, Pre-Sized Parallel TSV Emission, Uncapped Content-Compare Write Skip & Incremental Sync Hot-Path Optimization (`emitter.rs`, `scanner.rs`, `resolver.rs`, `sharder.rs`, `graph.rs`, `lib.rs`, `main.rs`)**:
  - Changed `emitter::sanitize_tsv(&str) -> Cow<'_, str>` (and `escape_table`) to use a byte-scan fast path (`is_clean_tsv_str`) that returns `Cow::Borrowed` when no control characters, tabs/newlines, leading/trailing spaces, or consecutive spaces are present, and a single-pass `String::with_capacity` builder otherwise.
  - Pre-sized all six `index/*.tsv` buffers in `emit_bundle`, formatted `calls.tsv` and `xref.tsv` with direct string/integer pushes (`push_usize`) and `sections.tsv`/`symbols.tsv`/`types.tsv`/`macros.tsv` with `std::fmt::Write`, and parallelized in-memory Markdown/TSV formatting and output writes via `rayon::join`.
  - Updated `emit_cache_shards` to read `cache/` once via `fs::read_dir`, reuse `structural_digest` from the previous `cache/manifest.json` when `blake3_hash` and `shard` match, write only missing or changed shards, and prune orphaned `.json` shards from the directory set.
  - Removed the 256 KB size cap in `write_file` so unchanged large tables (`calls.tsv`, `xref.tsv`) compare existing bytes whenever `fs::metadata` length matches and skip redundant disk writes (preserving file mtime), and eliminated the duplicate `meta.json` write inside `emit_bundle` so `meta.json` is written once per conversion with final timings.
  - Replaced full-file TSV reads in `scanner::first_missing_bundle_artifact` with 512-byte header-line reads (`read_tsv_header_line`), deferred full bundle-completeness checks to cache-hit/short-circuit gates, disabled parent/global git-config walking in `WalkBuilder`, and precomputed symbol/import path metadata with parallel per-unit resolution in `resolver::resolve_and_link` and `sharder::build_section_shards`, reducing 123-file `smart_locker` incremental structural sync from `477 ms` (`emit = 265 ms`) to `85–95 ms` median (`emit = 21–25 ms`).

### Added

- **Core Source-to-Agent Extraction Engine (`crates/chipsrc-core`)**:
  - Parallel `.gitignore`-aware repository scanner (`scanner.rs`) with BLAKE3 file and tree fingerprinting (`meta.json`) for sub-2ms incremental cache hits.
  - Multi-language Tree-sitter AST parser (`parser.rs`) supporting C, C++, Rust, Python, TypeScript, and JavaScript without LLM calls or build-system compilation.
  - Structural extraction modules (`symbols.rs`, `types.rs`, `calls.rs`, `macros.rs`) for function/method signatures, struct/enum/trait/type definitions with byte/field layout, static caller->callee edges, `#define` / `const` constants, and peripheral MMIO register / ISR vector usage.
  - Unified Code + Hardware Cross-Reference Graph (`xref.rs`) linking functions, types, macros, call edges, and hardware registers/peripherals across the codebase (`index/xref.tsv`).
  - Hierarchical Agent Codebase Bundle emitter (`sharding.rs`, `emitter.rs`, `sanity.rs`) producing `INDEX.md`, module-sharded `sections/*.md` signature skeletons, flat `index/*.tsv` tables, `meta.json`, and `.claudeignore` prompt-cache protection.

  - `chipsrc status [--compact]`: Scans the workspace for ready bundles and unindexed source trees.
  - `chipsrc ensure <repo_dir...> [-o output/]`: Indexes source repositories with `<2ms` BLAKE3 incremental cache hits.
  - `chipsrc sym <query> [--compact]`: 1-turn function/method signature, docstring, location, and call-summary lookup.
  - `chipsrc type <query> [--compact]`: 1-turn struct/enum/union/trait/class definition and field layout lookup.
  - `chipsrc callers <symbol>` and `chipsrc callees <symbol>`: Static call-graph traversal (direct and multi-hop).
  - `chipsrc macro <query>`: `#define` / `const` / register address constant lookup with C/vendor hex normalization (`0x400` <-> `400h`).
  - `chipsrc xref <symbol>`: Unified Code + Hardware Cross-Reference Graph traversal across symbols, types, macros, and hardware peripherals.
  - `chipsrc section [bundle] [query]` and `chipsrc body <file:line|symbol>`: Module skeleton slice and exact on-demand function body extraction from source.
